# Mini CDR — Module 06: ML Knowledge Graph (A06)

```
Mini CDR — Module 06: ML Knowledge Graph (A06)
|
├── Problem / Prompt
|   └── Map Daniel Bourke's Machine Learning Roadmap as a knowledge graph
|       in Whimsical, representing major domains as primary nodes and
|       subtopics/dependencies as secondary nodes and cross-branch
|       connections.
|
├── Approach
|   └── Used the Mind Map template with "Machine Learning" as the root,
|       five primary branches (Foundations, Learning Approaches,
|       Techniques, Tools and Frameworks, Applications), then added
|       dashed connector lines specifically to surface dependencies that
|       cross branches rather than staying within one.
|
├── What worked
|   └── Explicitly looking for cross-branch dependencies (not just
|       filling in subtopics under each branch) is what turned this from
|       a static outline into something that actually taught me
|       something — e.g., realizing Cloud Platforms and Version Control
|       support all four Learning Approaches, which I hadn't planned for
|       going in.
|
├── What didn't / had to change
|   └── Initial node layout had connector lines overlapping and hard to
|       read once multiple cross-branch dependencies were added; had to
|       manually reposition nodes to keep the diagram legible.
|
├── What I'd do differently next time
|   └── Decide the granularity rule (what counts as a secondary node)
|       before starting to place nodes, rather than adjusting it
|       mid-build — the roadmap is large enough that inconsistent
|       granularity created rework.
|
└── Key concept takeaway
    └── The ML landscape isn't a sequential curriculum — it's a system
        where a few nodes (Python, Cloud Platforms, Version Control)
        function as infrastructure that every other branch depends on
        simultaneously, not a prerequisite you finish once and move
        past.
```
